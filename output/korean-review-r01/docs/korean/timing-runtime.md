# 시간 제한 입력의 조기 실현성 검사

[채택한 실행 증거](../evidence/korean/timing-probe.json)는 원래 뱀 장면
`ROOM 9.0`의 스크립트·그림·음향 코드·키보드 경로를 실행한 합성 비교다.
번역 적용이나 전체 진행 검증은 아니다. 승인되지 않은 번역의 **셀 수와 줄바꿈만**
사용하며 화면에는 반복 `가`를 출력한다.

## 콜드 부팅 비교

네 프로필을 각각 무입력, 0.10초 후 `SHOOT`, 1.50초 후 `SHOOT`로 실행했다.
총 12개 실행은 같은 Apple II+ 48K + LC 프로필과 소유 MAME 프로세스를 사용한다.
INITIAL의 마지막 전환만 `.S P=1` → `.G ROOM 9.0`으로 바꿔 원래 초기 인벤토리로
뱀 장면에 들어간다. 실행 중 PC·월드·키보드 버퍼를 쓰지 않는다. 키 입력은 MAME의
자연 키보드 경로를 사용한다. 한국어 런타임 프로필은 추가 DOS 디스크에서 LC 자산을
읽은 후 단일 드라이브에서 합성 게임 A로 교체한다.

| 프로필 | 출력 경로 | 실행 중 확인한 방 본문의 한글 글리프 |
| --- | --- | ---: |
| native | 원래 영문 스크립트와 프린터 | 0 |
| reference | 영문 본문 + 메시지 참조·LC 풀 | 0 |
| draft | 초안 셀/공백/줄바꿈 형태, 공백 외 모든 글자를 `가`로 치환 | 80 |
| stress | 각 메시지를 39글자 × 3행의 합성 한글로 치환 | 468 |

각 실행은 방 본문 네 메시지를 출력한다(진입 두 개와 성공 또는 실패 두 개).
참조 경로에서는 메시지 호출/정상 반환이 각각 네 번이며 잘못된 참조 반환은 없다.
글리프 경로도 실제로 실행되었는지 센다. 따라서 출력을 건너뛴 결과로 시간이
같아졌다고 판단한 것이 아니다. stress는 출력 부하 검사이며 최종 화면 배치가 아니다.
LC의 최대 풀·글리프 경계는 별도의 [메시지 검사](message-runtime.md)가 담당한다.

## 결과와 측정 경계

무입력일 때 원래 뱀은 여덟 번의 첫 글자 입력 기회를 준 뒤 플레이어를 죽인다.
네 프로필 모두 각 반복의 측정 구간은 **1.623072초**였고, 측정값의 차이는
부동소수점 시간 표현의 반올림 수준이었다. 검사 허용치는 원판 대비 1% 이내다.
모든 실행에서 이 구간 중 Disk II/RWTS 요청은 0회였다.

측정 시작은 `!TIME`의 `.S B=0` intrinsic 진입, 끝은 `B=250`인 마지막
`.I B<250` intrinsic 진입이다. 키가 있으면 `$C000`에서 관찰한 첫 strobe로 끝을
기록한다. 실제 마지막 키 검사와 루프 반환 사이의 명령까지 하나의 시간으로
뭉뚱그리지 않고, 모든 프로필에서 같은 소스 지점을 비교한다.

0.10초와 1.50초는 **키를 큐에 넣도록 요청한 시간**이며 실제 수신 시각은 별도
기록한다. 늦은 입력의 첫 `S`는 약 1.576–1.582초에 관찰됐다. 모든 프로필이
`S`, `H`, `O`, `O`, `T`를 각 문자 창에서 받았고 원래 성공 파일 `ROOM 9.2`에
도달했다. 무입력 실행은 모두 `DEATH`에 도달했다.

이 장면의 출력과 그림 전환은 카운터 반복 밖에서 실행된다. 한글 출력이 장면의
진행 속도에는 영향을 줄 수 있지만 측정한 입력 창을 줄이지 않았다. 부팅·그림 적재의
디스크 배치도 프로필마다 다르므로 장면 진입부터 첫 창까지의 전체 시간 차이를
순수한 글꼴 렌더링 비용으로 해석하면 안 된다.

## 원천 타이머 조사와 남은 실행 검사

[정적 목록](../evidence/korean/timer-inventory.json)은 87개 텍스트 스트림 중 DOS EXEC
START를 제외한 86개 스크립트를 조사했다. 19개 파일에 Q 검사 25개, `.W` 지연 42개,
R 초기화 16개와 `!TIME` 라벨 9개가 있다. Q 비교에는 `SHOOT`의 각 글자 비교도
포함되므로 이를 25개 독립 타이머로 해석하지 않는다. 각 위치의 원래 줄/오프셋과
파일 해시를 기록한다.

| 장면/파일 | 원래 제어 흐름에서 확인한 특징 | 남은 검사 |
| --- | --- | --- |
| 뱀 A `ROOM 9.0` | 문자별 250회 Q 폴링, 출력/그림은 창 밖 | 승인 번역과 실제 전체 진행에서 반복 |
| 유령 A `ROOM 15.0` | NV(15) 증가 후 `.W`, 250 초과 시 소멸; 단서 질문은 NV를 210으로 설정 | 기다림·질문·명령 재진입/소멸 |
| 해골 A `ROOM 17.0` | 화면을 바꾸고 경고를 다시 출력하는 루프, N1(17) 누적 및 Q 검사 | 반복 경고의 한글 비용과 반응 성공/실패 |
| 가스 B `ROOM 36.0` | B를 증가하며 100회 한계, 첫 키가 명령 입력으로 연결 | 탈출·늦은 반응·다른 명령 |
| 징검다리 B `ROOM 39.0` | D의 안전/위험 위상과 B/C 지연을 번갈아 적용 | 두 위상의 Return, 다른 키로 후퇴 |
| Roboff B `ROOM 49.0` | B 100회 한계, 첫 키를 받은 뒤 명령 처리 | GIVE MASK와 지연/잘못된 행동 |
| 재규어 B `ROOM 49.2` | B=80에서 그림·대사·울음 후 타이머 계속, 150에서 공격 | 중간 경고 포함 양쪽 반응 창 |
| A14, B31/31.1, B37, B42, B46 | 바위/깜박임/페이지 대기/효과음/붕괴 연출과 Q 폴링 | 단순 페이지 대기와 위험한 타이머를 구분해 회귀 |

특히 해골과 재규어는 반복 중 출력·그림·소리가 있으므로 뱀의 결과를 그대로
일반화하지 않는다. 원래 카운터/조건·영문 입력 토큰을 보존하고 새 디스크 읽기나
페이지 대기를 넣지 않는 원칙을 유지한다. 승인 후 K6에서는 위 장면과 엔딩을
전체 경로로 검증해야 한다. 실제 Apple II+ 검증은 아직 하지 않았다.

## 재현

```sh
python3 tools/korean/audit_timers.py
python3 tools/korean/verify_timing.py \
  --rompath /path/to/roms --output build/korean/timing-validation-new
```

출력 경로는 새 디렉터리여야 한다. 각 fixture의 빌드·매체 해시와 원래/변환 스크립트의
측정 지점을 기록한다. `startup_disk.py`의 기본 opening 프로필은 유지하며,
`--scene snake --synthetic-shape draft|stress`는 이 실험 전용이다.
