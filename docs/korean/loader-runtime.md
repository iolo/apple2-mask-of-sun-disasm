# DOS 스트리밍 로더 합성 검증

`src/korean/loader.s`는 KOR2 패키지를 원래 Disk II/RWTS로 읽는다. LC/메시지/참조
래퍼와 함께 main RAM `$9400–$9B19`의 1,818바이트에 연결된다(게임 진입 dispatcher 포함). 예약한 2KB 영역의
나머지는 230바이트다. [추가 디스크 콜드 부팅](startup-runtime.md)은 합성 시작 경로를 통과했다.

## 인터페이스와 메모리

`ko_load_package`: A/X에 원래 방식의 high-bit 10바이트 파일명 포인터,
`$EC/$ED`에 목적지 `$6800` 또는 `$7000`을 전달한다. 대상은 원본 `.G`/초기화
호출에 연결하는 후보 API다. 합성 부팅에서는 조건부 interpreter가 dispatcher를 거쳐 호출한다.

성공은 C=1, 실패는 C=0이다. `ko_load_error`는 다음 값을 갖는다.

| 값 | 의미 |
| --- | --- |
| 0 | 성공 |
| 1 | 실제 RWTS 읽기 오류 |
| 2 | 파일명 없음 |
| 3 | 잘못된 magic, TS/카탈로그 메타데이터, 또는 스크립트 마지막 EOF 누락 |
| 4 | 목적지·스크립트·풀 크기 범위 초과 |
| 5 | 선언된 길이를 읽기 전에 TS 항목이 끝남 |
| 6 | 다른 빌드 식별값 또는 허용되지 않은 디스크 면 |

- 카탈로그/TS-list 버퍼는 원래처럼 `$B700`이다. 단일 TS-list만 허용한다.
- 섹터 버퍼는 `$0700–$07FF`다. 처음 제안한 `$0400`은 RWTS의 `$0478` 및
  slot별 드라이브 위치와 충돌하므로 사용하지 않는다. `$0578`, `$05F8`, `$0678`,
  `$06F8`도 RWTS 작업 영역이다. 이 소스에는 `$0700` 페이지 참조가 없다.
- 스크립트는 `$6800`에 최대 2KB 또는 `$7000`에 최대 9KB를 적재한다.
  LIBRARY의 상한은 `$9400` 확장 코드 시작점이며 원래 11KB 전체를 쓰지 않는다.
- 메시지 풀은 LC bank2 `$D000`에 최대 1KB를 적재한다. 헤더와 스크립트가
  섹터 중간에서 끝나도 스트림 위치를 유지하여 이어서 풀로 복사한다.
- 버퍼에는 한 섹터만 읽는다. LC가 ROM을 가린 상태에서는 RWTS를 호출하지 않는다.
  LC 쓰기마다 IRQ mask를 보존하고 main RAM에서 ROM을 복구한 뒤 다음 읽기를 한다.
- 로드 시작 시 `ko_room_size=0`으로 캐시를 무효화한다. 모든 바이트를 읽은 뒤에만
  새 풀 크기를 공개한다. 상주 풀·공통 글꼴은 이 API가 변경하지 않는다.

이 API는 실패 메시지, 디스크 교체, 재시도 또는 스크립트 재개를 수행하지 않는다.
호출자는 C=0일 때 부분 적재된 스크립트를 실행해서는 안 된다. 합성 dispatcher는
영문 교체 안내를 출력하고 전체 파일을 재시도한다. 최종 매체 식별/UI는 남아 있다.

24바이트 헤더는 `KOR2`, 스크립트/풀 길이(u16 두 개), 빌드 식별값 12바이트,
면 비트마스크(A=1/B=2/공유=3), 예약 0바이트 세 개다. 빌드 식별값과 면을
스크립트/LC 본문 쓰기 전에 검사한다. 원래 안내와 같이 `$601C`의 GE(12)가
2 이상이면 B, 그 외에는 A를 요청한 상태로 판단한다. INITIAL/LIBRARY/DEATH는
초기화·사망 전환에서 공통으로 쓰이므로 명시적으로 공유를 허용한다.

식별값은 패키지 본문과 면 정책, 글꼴·상주 자료·런타임 및 소스/영문 기준선으로
결정한다. 합성 시나리오가 스크립트를 바꾸면 최종 본문으로 다시 계산하여 모든
패키지와 런타임을 함께 바인딩한다. KOR1이나 다른 빌드를 허용하는 우회는 없다.
이는 빌드 혼용 방지이며, 읽은 본문 전체의 런타임 체크섬 검증은 아니다.
그림 등 native 로더 자산의 식별과 전체 매체 통합은 아직 남아 있다.

`ko_load_pool`은 저장된 방 스크립트를 보존하고 LC 풀만 다시 읽는 진입점이다.
헤더/본문 EOF를 검사하며 실패 시 풀을 무효화한다. [저장 검사](save-runtime.md)에서
실제 방 파일 재적재와 스크립트 보존을 확인했다.

## 검증

```sh
python3 tools/korean/verify_loader.py \
  --rompath /path/to/roms --output build/korean/loader-validation-new
```

검증기는 소스에서 재빌드한 영문 A 디스크의 복사본에서 선택한 스크립트 파일과
TS-list만 합성 데이터로 바꾼다. 원본/기준선 이미지의 해시는 보존한다. 일부 TS-list는
실패 검사를 위해 의도적으로 손상했으므로 이 이미지는 배포/게임 진행용이 아니다.
번역 카탈로그를 읽거나 실제 한국어 본문을 적용하지 않는다.

원래 DOS 부트와 `START`를 실행하고 인터프리터 `$0800` 진입의 명령 경계에서
테스트 하네스로 전환한다. 기존 RWTS와 드라이브 위치 초기화를 사용한다. RWTS나
디스크 읽기 결과를 mock으로 대체하지 않는다.

[채택한 증거](../evidence/korean/loader-probe.json)의 26개 사례는 다음을 확인한다.

- 잘못된 목적지, magic, 방/라이브러리/풀 크기, EOF, 추가 TS-list, 범위 밖 TS,
  빈 TS-list 및 없는 파일을 거부한다.
- 실제 디스크의 volume 254에 대해 IOB의 요구 volume을 1로 지정하면 RWTS가
  carry와 `$20` 오류를 반환하며 로더는 오류 1로 전달한다.
- 다른 빌드, 잘못된 면 및 KOR1을 본문 적재 전에 거부한다. B면/공유 자원의
  성공, 복원용 pool-only 경로의 빌드/면 거부도 검사한다. 거부 후 main 스크립트와
  LC 풀 바이트가 모두 이전 값과 같고 캐시 유효 크기는 0이다.
- 스크립트 232바이트 적재 후 및 풀 473바이트 적재 후 발생하는 잘린 스트림에서
  캐시 크기는 0으로 남는다. 헤더 단계에서 거부한 파일은 기존 스크립트/라이브러리를
  변경하지 않는다.
- 1,023바이트 스크립트 + 1,000바이트 풀을 8개 섹터에서 나누어 읽고 바이트를 대조한다.
  다른 방, 풀 없는 방, 9,216바이트 라이브러리 및 재적재도 검사한다.
- 디스크에서 읽은 메시지가 LC reader와 참조 래퍼를 통해 출력되며 HGR1 8KB가
  호스트 기대값과 일치한다. 이 시험의 메시지는 합성 ASCII이며 한글 출력은
  [별도 46사례 메시지 시험](message-runtime.md)에서 검사한다.
- 확장 코드, `$67FF` 경계 표식, 상주 LC 4KB, bank2 나머지 3KB, 공통 영역 8KB가
  보존된다. 하드웨어 스택, 호출자의 IRQ mask 및 ROM 복귀도 검사한다.

RWTS의 IOB+13은 carry가 설정된 경우에만 오류 코드로 해석한다. 이 원본 RWTS는
성공 시에도 마지막 A 값을 그 바이트에 저장하므로 0이 아닌 값 자체는 실패가 아니다.

## 남은 작업

추가 디스크 초기화와 시작 경로의 게임 연결은 별도 합성 검사를 통과했다.
[별도 저장 복원 검사](save-runtime.md)는 시작 경로의 새 부팅 및 부분 실패 재시도를 통과했다.
[전체 합성 실행](full-media-runtime.md)은 86자원 적재와 B면 복원을 통과했다.
최종 게임 매체 검증, 승인 교체/재시도 UI, 엔딩·나머지 시간 제한 검증이
필요하다. `$9400` 코드는 저장 스냅샷 범위에 있으므로 복원 중 실패 복구는 별도
보존 영역 `$1F6E–$1FFF`에 두었다. 로더 개별 검사는 복원 경로를 대신하지 않는다.
