# 추가 DOS 디스크 콜드 부팅 합성 검증

[채택한 증거](../evidence/korean/startup-probe.json)는 추가 140K DOS 디스크에서
Apple II+ 48K + Language Card를 콜드 부팅한 결과다. 디버거의 실행 코드·PC·월드
주입 없이 DOS `START`, `BLOAD`, Disk II/RWTS와 실제 키 입력으로 진행했다.
원래 영문 메시지와 `한국어 합성 시험 ABC 123`이라는 시험용 제목만 사용했다.
미승인 한국어 번역 카탈로그를 읽거나 정식 한국어 디스크를 만들지 않는다.

## 부팅과 배치

1. 추가 디스크의 `START`가 조건부 한국어 인터프리터, 원래 PARMS, `$5000`의
   임시 부트 코드 1,152바이트를 적재한다.
2. 부트 코드가 `$9400`에 런타임 1,818바이트를 읽고 LC 존재를 검사한다.
3. 5,200바이트 글꼴을 LC 공통 `$E000`에, 4,096바이트 풀을 bank1 `$D000`에
   섹터 단위로 읽는다. 실제 합성 상주 풀은 4,093바이트이며 끝에 패딩을 넣었다.
   사용 한글 7개 뒤에는 실제 글꼴을 추가하여 전체 초안의 650글리프 용량을 모사한다.
4. 원래 `$0800` 진입점에서 INITIAL/LIBRARY의 KOR2 패키지와 원래 intrinsic,
   renderer, LOGO를 읽는다. INITIAL의 HGR page-2 지우기가 임시 부트 코드를 덮어쓴다.
5. ROOM 1.0이 없는 추가 디스크에서 게임 디스크 요청을 표시한다. 단일 드라이브의
   매체를 교체하고 Return을 누르면 같은 파일 전체를 다시 읽는다.
6. 방 패키지의 스크립트는 main RAM, 메시지 풀은 LC bank2 `$D000`으로 적재한다.
   실패 때는 풀 크기를 0으로 유지하고 부분 스크립트를 실행하지 않는다.

`src/interpreter.s`의 `KOREAN` 조건부 심볼 연결로 출력 및 로더를 선택한다.
조건을 사용하지 않은 기본 영문 A/B 재빌드는 기존 기준 해시와 같았다.
원래 파일 로더 본문은 남겨 두며 그림·intrinsic·renderer 파일 적재에 사용한다.
참조화된 LIBRARY는 9,125바이트로 `$93A4`에서 끝난다. 런타임은
`$9400–$9B19`이며 예약한 2KB 안에 230바이트가 남는다.

추가 디스크는 부트 트랙, 카탈로그 트랙, 파일별 TS-list와 섹터 반올림을 포함하여
345섹터가 남는다. 합성 A 디스크는 방 1–7 등의 시작 경로만 포함하므로 남은
118섹터를 최종 전체 A 디스크의 여유로 해석하면 안 된다. 전체 초안의 별도
[호스트 패킹](encoding.md)과 이 부팅 실험을 최종 배포 배치로 통합하는 작업은 남아 있다.

## 임시 부트의 월드 메모리 보존

KOR2 면 검사에서 이전 `$6000` 배치의 문제가 드러났다. INITIAL은 모든 월드
바이트를 초기화하지 않으며 GE(12)에 부트 코드 `$A9`가 남아 정상 A를 B 상태로
오인했다. 부트는 HGR page-2의 `$5000–$547F`로 이동했다. 초기화 전에 쓰는
임시 그림 영역이며 LC 적재가 끝난 뒤 INITIAL이 지운다.

초기 합성 검사는 부트 진입 전후 월드 2KB의 완전 보존만 확인했다.
이 검사는 초기 RAM이 0인 MAME에서 GE(12)의 미초기화를 놓쳤다.
사용자 보고 후 Apple2TS 및 GSSquared에서 비영(非零) 초기값 문제를 재현했다.

r01-fix1은 부트가 엔진 진입 전에 **GE(12), `$601C`만 0(A면)으로 초기화**한다.
나머지 2,047바이트는 보존한다. 이는 디버거 우회가 아니라 배포 부트 코드의
명시적 초기화다. 이후 B면 전환과 저장 복원은 게임이 관리하며 초기값을 다시
강제하지 않는다. 부트 크기는 1,157바이트(`$5000–$5484`)다.
[수정 및 회귀 기록](disk-swap-fix1.md)을 참조한다.

## 확인한 동작

- 부트 디스크에서 읽은 글꼴 5,200바이트와 상주 풀 4,096바이트를 기대값과 비교했다.
- 제목 행의 일곱 한글 글리프 픽셀을 독립적으로 비교했다.
- 원래 영문 A 디스크를 넣으면 KOR2 magic 오류로 거부하고 캐시를 무효화한다.
  이때 상주 풀과 글꼴은 보존되며 올바른 합성 A로 교체 후 재시도할 수 있다.
- `LOOK`, `INVENTORY`, `EXIT PLANE`, `GET MAP`, `ENTER JEEP`를 입력하고
  페이지 대기를 진행하여 방 1 → 2 → 3에 도달했다. 최종 방의 풀은 118바이트다.
- 각 명령 프롬프트에서 LC 상주 자료가 그대로인지 확인했다.
- LC 없는 48K 프로필은 `16K LANGUAGE CARD REQUIRED.`와 재시작 안내를 출력하고
  게임으로 진입하지 않는다.
- 동일 런타임의 메시지 46사례와 로더 26사례 회귀 검사도 통과했다.
- 두 번 생성한 시작/합성 A 이미지와 부트·인터프리터·세 자산 파일의 바이트 및
  해시가 일치했다. 호스트 검사 32개와 카탈로그 검사도 통과했다.

## 재현

```sh
python3 tools/build.py --output build/korean/english-baseline
python3 tools/korean/verify_startup.py \
  --rompath /path/to/roms --output build/korean/startup-validation-new
```

출력 경로는 새 디렉터리여야 한다. 검증기는 자체 생성한 DOS 디스크와 기준 영문
디스크의 복사본만 마운트한다. 기존 원본/기준선 파일을 수정하지 않는다.

## 남은 실현성 조건

이 결과는 DOS 방식의 시작 경로를 검증한 것이며 K4 전체 완료가 아니다.

- [저장/새 부팅 복원](save-runtime.md)은 별도 합성 시작 경로에서 통과했다.
  `$1F6E–$1FFF` 복구 코드와 방 풀 재적재를 사용한다. B면 복원은
  [전체 합성 실행](full-media-runtime.md)에서 통과했으며 엔딩/승인 번역 검증은 남아 있다.
- 모든 A/B 자원, 디스크 전환, 사망·재시작, 시간 제한 장면 및 엔딩 검증.
- 자산 헤더의 빌드별 magic/길이/식별값과 KOR2 방 패키지의 빌드/면을 검사한다.
  payload 전체 해시를 읽을 때 다시 계산하지는 않는다. 그림 등 native 자산의
  혼용과 본문 손상까지 검출하는 최종 매체 검증은 남아 있다.
- 현재 교체 문구는 합성 실험용 공통 영문 안내다. 최종 요청 매체 식별과 승인된
  안내, 오류 처리 및 저장 디스크 동작을 통합해야 한다.
- 전체 번역의 화면 결합·영문 입력·퍼즐 검토와 사람 승인, 실제 Apple II+ 검사.

이 시험에서 ProDOS가 필요한 근거는 발견하지 못했다. ProDOS 이식은 시작하지
않았으며, 필요하다고 판단하면 작업을 멈추고 사용자 결정을 요청한다.
