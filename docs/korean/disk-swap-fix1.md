# r01-fix1: EXTRA → A 교체 후 진행하지 않는 문제

증상: EXTRA로 부팅한 뒤 정상 한국어 A 디스크를 같은 드라이브에 넣고 RETURN을
눌러도 디스크 안내가 다시 표시된다. 사용자는 Linux AppleWin(sa2)와 GSSquared에서
보고했다. GSSquared와 Apple2TS에서 같은 실패를 재현했다.

원인은 `$601C`, GE(12)의 초기값이다. 원래 INITIAL은 이 값을 설정하지 않는다.
한국어 로더는 A/B 자원 검증에 이 값을 사용하며 2 이상이면 B로 판정한다.
MAME의 기존 시험에서는 0이었지만 Apple2TS에서는 `$FF`여서 올바른 A 자원을
오류 6으로 거부했다. RETURN은 정상적으로 처리되었고 디스크의 빌드 식별값도
일치했다. 이전 부트 코드의 월드 영역 침범을 제거한 것만으로는 초기 RAM 값에
대한 의존성이 해결되지 않았다.

수정은 `src/korean/bootstrap.s`의 엔진 진입 직전 `LDA #0 / STA $601C`다.
초기 게임 면을 A로 명시하며 다른 월드 바이트는 보존한다. 게임 중 B 전환 및
저장 복원에는 이 초기화를 적용하지 않는다. 부트는 5바이트 증가한 1,157바이트이며
디스크 여유(A 2/B 6/EXTRA 344섹터), 런타임 1,841바이트, 승인 번역은 그대로다.

검증:

- GSSquared enhanced IIe: 부트 실행 직전 GE(12)를 `$FF`로 설정하면 구버전은
  A 삽입/RETURN 후 오류 6을 재현한다. 수정판은 부트에서 0으로 설정하고 동일한
  교체/RETURN으로 첫 방의 명령 입력까지 도달한다. PC·스크립트·로더 패치는 하지 않았다.
- Apple2TS enhanced IIe: 실제 `$FF` 초기값의 구버전 실패를 확인했다. 수정판은
  부트 전 `$AA`를 넣은 경우에도 A 수용, 방 1, 로더 오류 0, 명령 입력 지점에 도달했다.
- MAME Apple II+ 48K + LC: 수정 매체로 66명령 A→B 경로와 B면 동일 세션 저장/복원,
  새 부팅 복원이 통과했다. 승인 메시지 1,327항목과 재현 빌드 10개 산출물을 대조했다.
- 호스트 검사 44개가 통과했다. AppleWin 자체의 실행과 실제 하드웨어는 이번에 검사하지 않았다.

회귀 도구: `tools/korean/verify_disk_swap.py`. 증거는
`docs/evidence/korean/approved-r01-fix1-*.json`에 있다.

**새 ZIP의 EXTRA/A/B 세 장을 모두 교체해야 한다.** 부트 변경으로 매체·저장 식별값이
바뀌었으므로 구판 디스크와 혼합하지 않는다. 새로 제공한 빈 저장 디스크의 복사본을
사용한다. 구판과 검수 묶음은 재현 자료로 보존했으며 번역 재승인은 필요하지 않다.
