# 한국어 인코딩·배치 후보

이 문서는 K3 이전의 **호스트 실험**이다. 번역은 전부 draft이며 게임에 적용하거나
승인하지 않았다. 실행 검증을 마칠 때까지 인코딩과 주소는 후보로 취급한다.
원본 A/B 디스크, DOS 부트, 원본 그림·입력 패턴은 이 실험에서 변경하지 않는다.

## 재현

```sh
python3 tools/korean/catalog.py check
python3 tools/korean/encoding.py
python3 -m unittest discover -s tools/korean -p 'test_*.py'
```

산출물은 `build/korean/draft-encoding/`에 둔다. `encoding.json`은 카탈로그·도구·폰트
해시, 파일별 원본/변환 크기와 패키지 해시, 디스크별 할당 결과를 기록한다.
`allocation-a.json`, `allocation-b.json`은 실제 트랙/섹터 번호를 가진 호스트 배치다.
디스크 이미지나 실행 가능한 한국어 게임을 만들지는 않는다.

## 스트림

- `$20–$7E`: 1바이트 ASCII. 기존 글꼴과 위상 비트를 사용한다.
- `$80–$BF`, 뒤의 1바이트: 14비트 비ASCII 글리프 ID. ID는 정렬된 문자 목록의 순서다.
  뒤쪽 바이트가 `$00`, `$0A`, `$8D`여도 데이터이며 제어로 해석하지 않는다.
- `$0A`: 메시지 내부 줄바꿈. `$00`: 메시지 끝. 나머지 단독 제어값은 오류다.
- 문자열 끝의 원래 줄바꿈/이어 쓰기는 스크립트의 세미콜론 유무로 결정한다.
- 풀은 `u16 메시지 수`, `u16 오프셋 배열`, 종료자를 포함한 메시지 데이터 순서다.
  정수는 little endian이고 오프셋은 풀 시작 기준이다. 같은 바이트열을 공유한다.
- 스크립트의 번역 대상 리터럴만 5바이트 high-bit ASCII `~hhhh`로 바꾼다.
  ID의 bit15가 1이면 상주 풀, 0이면 현재 파일의 풀이다. CR, 조건, 매크로,
  상대 줄 점프, 세미콜론, 제외한 명령 에코는 원본 바이트를 보존한다.
  모든 원래 참조 위치의 바이트를 대조하고 CR 개수가 달라지면 실패한다.

파일별 후보 패키지는 24바이트 KOR2 헤더, 스크립트, 풀이다. 헤더에는 `KOR2`,
`u16 스크립트 길이`, `u16 풀 길이`, 빌드 식별값 12바이트, A/B/공유 비트마스크,
예약 0바이트 세 개가 들어간다. [로더](loader-runtime.md)는 본문 쓰기 전에
빌드/면/예약값을 검사한다.
스크립트 길이에는 EOF가 포함된다. 이는 **새 스트리밍 로더 전용**이다. 기존의
연속 RAM 로더에 그대로 전달하면 안 된다. DOS EXEC 파일 `START`는 포장하지 않는다.

## 전체 초안 측정

현재 카탈로그의 1,388항목 중 1,327항목에 초안이 있고 61항목은 사유가 있는 제외다.
본문은 총 37,128바이트로 인코딩된다(중복 제거 전, 종료자 포함). 원문/번역별 인코딩
왕복 비교와 폰트 변환이 통과했다. 모든 명시적 번역 행은 40셀 이내다.
[호스트 화면 미리보기](layout-review.md)는 연속 출력 403조합을 검사했다.
실제 출력 시작 위치·블록 간 결합·화면별 총 행수 검사는 별도로 필요하다.

| 자료 | 크기 |
| --- | ---: |
| 비ASCII 글리프 650개 | 5,200바이트 |
| 상주 풀(152개 고유 본문, 353개 카탈로그 항목 참조) | 4,089바이트 |
| 최대 방별 풀(B `ROOM 43.0`) | 1,013바이트 |
| 세 자료의 합 | 10,302바이트 |
| LC 16KB에서 자료만 뺀 값 | 6,082바이트 |

상주 풀에는 LIBRARY, INITIAL, DEATH 및 별도 UI를 반드시 포함한다. 남은 4KB
예산에는 여러 파일에서 반복되는 미로·이동 문구를 우선 배치한다. 서로 다른 검수
항목은 그대로 유지하고 **동일한 번역 바이트열의 주소만 공유**한다. 승인 이후 번역이
바뀌면 다시 패킹해야 한다. 현재 상주 풀은 4KB 한계보다 7바이트 작지만 반복 문구를 내리는
것으로 재조정할 수 있다. 필수 상주 자료만으로 예산을 넘으면 도구가 실패한다.

개별 풀 파일 대신 스크립트와 풀을 함께 포장하여 파일별 반올림과 TS-list 증가를
피했다. 기존 스크립트의 섹터를 회수하고 실제 VTOC의 여유 섹터와 함께 재할당하면
A는 3섹터(768바이트), B는 6섹터(1,536바이트)가 남는다. 기존 각 파일의 TS-list와
카탈로그 위치는 유지한다. 실제 섹터 주소 중복, 보존 파일/메타데이터 침범 및
단일 TS-list의 122쌍 제한을 검사했다. 부트·코드 확장분은 아직 배치하지 않았다.
별도의 [전체 세 매체 용량 검사](media-capacity.md)는 조건부 코드·부트·추가 디스크의
중복 자산까지 실제 크기로 계산했다. 0바이트 대체 본문을 쓰는 전체 할당에서도
A 3/B 6/추가 345섹터가 남는다. 실제 게임 이미지를 만든 결과는 아니다.

이는 추가 디스크를 초기 자산 적재용으로 쓸 수 있다는 후보를 지지한다. 추가
디스크의 파일·카탈로그·청크 배치와 A로 복귀하는 부트 흐름은
[합성 콜드 부팅](startup-runtime.md)으로 검증했다. [전체 합성 실행](full-media-runtime.md)은 전체 초안의 크기를 보존한 세 이미지와 B면 복원도 검사했다. 승인 번역의 최종 통합은 남아 있다.
ProDOS가 필요하다는 증거는 없으며 이식은 시작하지 않았다.

## 다음 실행 실험에서 검증할 주소 후보

| 위치 | 후보 용도 | 주의점 |
| --- | --- | --- |
| LC bank1 `$D000–$DFFF` | 상주 풀, 최대 4KB | 오류/교체 안내도 여기서 읽는다. |
| LC bank2 `$D000–$D3FF` | 현재 파일의 메시지 풀, 최대 1KB | 현재 최대 1,013바이트. 캐시는 복원 후 무효화한다. |
| LC 공통 `$E000–$F44F` | 현재 초안 글꼴 5,200바이트 | 두 D-bank 선택과 독립적으로 유지한다. |
| main `$9400–$9BFF` | 새 코드 2KB 후보 | 참조화한 LIBRARY는 9,125바이트로 `$93A4`까지 사용. 실제 링커/적재 검증 필요. |
| main `$0700–$07FF` | 섹터 전송 버퍼 후보 | RWTS가 쓰는 `$0400–$06FF`의 작업 셀을 피한다. 합성 디스크 읽기 검증 통과. |

[메시지 런타임 실험](message-runtime.md)은 이 후보의 `$9400` 배치에서 793바이트 코드와
최대 LC 풀/폰트 접근을 검증했다. [스트리밍 로더 실험](loader-runtime.md)은 합성 DOS 파일에서 main/LC 분리 적재를 검증했다.
dispatcher를 포함한 통합 코드는 1,818바이트다. 추가 디스크 초기화와 방 1–3의
원본 영문 진행은 합성 콜드 부팅에서 통과했다. 전체 게임 검증은 남아 있다.

주소가 확정됐다는 뜻은 아니다. 특히 `$9400` 코드는 저장 스냅샷 범위에 들어간다.
복원 중 실행하는 코드와 실패 복구 안내는 이 영역에 의존하면 안 된다. 최소 복구
루틴을 `$1F6E–$1FFF`에 두고 동일 빌드 식별을 복원 전 검사하는
[합성 실험](save-runtime.md)은 시작 경로에서 통과했다. B면 합성 복원은 후속 전체 매체에서 통과했으며 엔딩/승인 번역 검증은 남아 있다.

복원 읽기 중 실패하면 부분 복원된 월드로 돌아가지 않는다. 동일 저장의 전체 재시도
또는 명시적 재시작 경로로 빠지도록 구현한다. 검증에는 A/B 저장, 새 부팅 복원,
잘못된 저장 매체, 중간 섹터 읽기 실패, 게임 매체 재삽입 및 캐시 재적재를 포함한다.

이후 합성 데이터로 실제 패키지 적재, LC 풀 읽기, ROM 복귀, 방 전환과 대표 시간
제한 장면을 검증한다. 이 검사와 화면/입력/퍼즐 검토를 마친 뒤 사람 검수를 요청한다.
