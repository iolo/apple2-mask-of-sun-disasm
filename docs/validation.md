# Validation commands and accepted evidence

Run from the checkout root with the prerequisites in [setup.md](setup.md).
Use a new generated directory for each emulator session/read audit. Scripts
control only their own copied media and emulator process. Recorded tests use
the same Apple II+ profile for original and rebuilt disks; `--fast` changes host
execution speed, not native emulated event timing.

## Build and boot

```sh
python3 tools/check_inputs.py
python3 tools/check_tools.py --build-only
python3 tools/build.py
python3 tools/verify_build.py --output build/source-audit
python3 tools/mame_session.py --rompath /path/to/roms --output build/boot-original \
  --headless --fast --script tools/boot_trace.lua
python3 tools/mame_session.py --rompath /path/to/roms --output build/boot-rebuilt \
  --disk-a build/disks/mask-of-sun-a.dsk --disk-b build/disks/mask-of-sun-b.dsk \
  --headless --fast --script tools/boot_trace.lua
python3 tools/verify_boot.py build/boot-original build/boot-rebuilt \
  --output build/boot-verification.json
```

The boot verifier checks native entry order, two-stage loads and payload
placement; its trace identity is diagnostic for this unchanged I/O layout.
[standalone-build.json](evidence/standalone-build.json) records two matching
builds and zero forbidden read dependencies. Gameplay gates below check behavior
independently of original disk/code identity.

## Full ending, scenes and sound

```sh
python3 tools/mame_session.py --rompath /path/to/roms --output build/full-original \
  --headless --fast --record-audio --script tools/opening_replay.lua --route docs/full-route.json
python3 tools/mame_session.py --rompath /path/to/roms --output build/full-rebuilt \
  --disk-a build/disks/mask-of-sun-a.dsk --disk-b build/disks/mask-of-sun-b.dsk \
  --headless --fast --record-audio --script tools/opening_replay.lua --route docs/full-route.json
python3 tools/verify_route.py build/full-original docs/full-route.json --output build/full-original.json
python3 tools/verify_route.py build/full-rebuilt docs/full-route.json --output build/full-rebuilt.json
python3 tools/compare_replays.py build/full-original build/full-rebuilt \
  --prompts 1 2 9 26 35 38 42 47 50 59 60 65 73 80 110 122 --output build/scenes.json
python3 tools/verify_audio.py build/full-original build/full-rebuilt --output build/audio.json
```

Full-route predicates preserve the native snake first-key input, ghost fade,
skeleton/gas response, stepping-stone safe phase and Roboff/jaguar reactions.
Both versions reach the ending with 83 pills. [pictures-full.json](evidence/pictures-full.json),
[scene/state comparison](evidence/full-scene-state-comparison.json) and
[full sound comparison](evidence/pictures-audio-full.json) are accepted final-content
evidence. Mixer samples are nonzero; recordings are verification artifacts rather
than native sound assets. Speaker effects are generated by the documented source.

## Commands, restart and saves

Use the same launch/verifier pattern with `docs/control-route.json`,
`docs/parser-route.json` and `docs/restart-route.json` for sound/input limits,
backspace/chaining/head carrying, and deliberate death/START respectively.
Control sound suppression requires `--record-audio`; inspect the accepted
[OFF/ON sample windows](evidence/audio-controls.json).

For saves, create an initialized disposable disk and pass it explicitly:

```sh
a2kit mkdsk --os dos33 --type do --volume 254 --dimg build/save-blank.dsk
python3 tools/mame_session.py --rompath /path/to/roms --output build/save-original \
  --save-disk build/save-blank.dsk --headless --fast \
  --script tools/opening_replay.lua --route docs/save-route.json
python3 tools/mame_session.py --rompath /path/to/roms --output build/save-rebuilt \
  --disk-a build/disks/mask-of-sun-a.dsk --disk-b build/disks/mask-of-sun-b.dsk \
  --save-disk build/save-blank.dsk --headless --fast \
  --script tools/opening_replay.lua --route docs/save-route.json
python3 tools/verify_route.py build/save-original docs/save-route.json
python3 tools/verify_route.py build/save-rebuilt docs/save-route.json
python3 tools/verify_save_disk.py build/save-blank.dsk build/save-original build/save-rebuilt \
  --output build/save-disk.json
```

`docs/save-side-b-route.json` applies the same procedure after travel to B.
`docs/restore-route.json` restores an existing saved disk after a fresh boot:
pass `--save-disk build/save-original/save.dsk` (or the rebuilt equivalent).
Reports compare all five complete object arrays and the 144-sector write footprint.
[behavior-matrix.md](behavior-matrix.md) links each accepted version and limits.

## Clean committed checkout

```sh
python3 tools/verify_checkout.py --output build/checkout-audit
```

This archives HEAD, removes all11 supplied inputs and195 reference-only regions
before running the documented tool check/build and a two-build read audit.
It needs git and strace in addition to build tools. Uncommitted edits are excluded.
Boot that tree's outputs with its own copied tools:

```sh
python3 build/checkout-audit/checkout/tools/mame_session.py --rompath /path/to/roms \
  --output build/checkout-boot \
  --disk-a build/checkout-audit/checkout/build/disks/mask-of-sun-a.dsk \
  --disk-b build/checkout-audit/checkout/build/disks/mask-of-sun-b.dsk \
  --headless --fast --script build/checkout-audit/checkout/tools/boot_trace.lua
python3 tools/verify_boot.py build/boot-original build/checkout-boot \
  --output build/checkout-boot.json
```

The original boot is independent validation reference data, not a clean-build
input. [Final audit](final-audit.md) records the actual committed revision and
requirement-by-requirement findings. The manual baseline's separate recording
method and checkpoint retry are in [manual-playthrough.md](manual-playthrough.md).
